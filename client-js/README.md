## casper-cep78-js-client

This JavaScript client gives you an easy way to install and interact with the Casper CEP-78 contract.

This package was created to help JS/TS users with the [cep-78-enhanced-nft](https://github.com/casper-ecosystem/cep-78-enhanced-nft) and is published in `npm` as the [casper-cep78-js-client](https://www.npmjs.com/package/casper-cep78-js-client). It was built on top of the [casper-js-sdk](https://github.com/casper-ecosystem/casper-js-sdk).

Users can treat this package as a Transaction sender for all of these possible interactions:

- contract installation including different configurations
- token minting
- token transfers
- token burning
- approvals
- changing configurations after installation
- getting or setting token metadata
- storing some of the contract-related data in an Account's `NamedKeys`

## Installation

To install, run:

`npm install casper-cep78-js-client`

Import the contract in your code:

`import { CEP78Client } from 'casper-cep78-js-client'`

If you want to install it, look at the `install` method and all of the possible configuration options (`InstallArgs`).

If you want to start working with a previously installed contract, use the `setContractHash(contractHash)` method.

## Development

Before installing the node modules, make sure the contract Wasm files are all generated by running the following in the CEP folder:

```bash
make build-all-contracts
```

After generating the Wasm files, you can install the client, and the Wasm will be automatically bundled.

```bash
npm install && npm run generate:wasm
```

> The `casper-cep78-js-client` requires `casper-js-sdk` and `@make-software/ces-js-parser` as a peer dependency.

> **IMPORTANT:** The class Client in client.ts is duplicated in every CEP JS client. Any modifications made to this class must be reflected across all instances of CEP clients to ensure consistency. Be sure to update all relevant CEP JS clients whenever changes are made to this class.

## Usage Examples

Create an instance of the CEP-78 client:

```ts
import {
  CEP78Client,
  ContractWASM as wasm,
  EVENTS_MODE,
  IDENTIFIER_MODE,
  OWNERSHIP_MODE,
  NFT_METADATA_KIND,
  METADATA_MUTABILITY,
  type InstallArgs,
  type TransactionParams,
  type TransactionResult,
} from 'casper-cep78-js-client';

const RPC_URL = 'http://localhost:11101/rpc';
const SSE_URL = 'http://localhost:18101/events'; // optional can be set later
const CHAIN_NAME = 'casper-net-1'; // optional can be set later or per query

const cep78 = new CEP78Client(RPC_URL, SSE_URL, CHAIN_NAME);
```

Send a transaction to install the contract:

```ts
const params: TransactionParams = {
  wasm, // optional, takes default Wasm in wasm folder if not set
  sender: sender.publicKey, // Public Key
  paymentAmount: String(600_000_000_000), // 600 CSPR
  signingKeys: [sender], // Private Key
};

const args: InstallArgs = {
  collectionName: 'TEST_CEP78',
  collectionSymbol: 'CEP78',
  totalTokenSupply = String(1000),
  eventsMode: EVENTS_MODE.CES,
  identifierMode: IDENTIFIER_MODE.Hash,
  ownershipMode: OWNERSHIP_MODE.Transferable,
  nftMetadataKind = NFT_METADATA_KIND.CustomValidated,
  jsonSchema = {
    properties: {
      ucid: { name: 'ucid', description: '', required: true },
      ipfs_cid: { name: 'ipfs_cid', description: '', required: true },
      color: { name: 'color', description: '', required: false },
    },
  },
  metadataMutability: METADATA_MUTABILITY.Immutable,
};

const transactionResult: TransactionResult = await cep78.install({
  params,
  args,
  waitForTransactionProcessed: true, // optional, waits for transaction process from SSE if SSE_URL is set
});
```

Set the contract hash (a unique identifier for the network):

```ts
cep78.setContractHash(
  'hash-c2402c3d88b13f14390ff46fde9c06b8590c9e45a9802f7fb8a2674ff9c1e5b1'
);
```

You can retrieve token information by calling these methods (non exhaustive list):

```ts
const collectionName = await cep78.collectionName();

const collectionSymbol = await cep78.collectionSymbol();

const tokenTotalSupply = await cep78.tokenTotalSupply();

const eventsMode = await cep78.eventsMode();

const numOfMintedTokens = await cep78.numOfMintedTokens();

...
```

# **Minting**

## **Minting a New Token**

The following example demonstrates how to mint a new NFT for a specified owner with metadata:

```ts
const tokenHash = 'my_custom_hash';

await client.mint({
  params: {
    sender: sender.publicKey,
    paymentAmount: String(5_000_000_000), // 5 CSPR
    signingKeys: [sender],
  },
  args: {
    tokenOwner: owner.publicKey,
    tokenMetaData: {
      ucid: tokenHash,
      ipfs_cid: 'QmbWqxBEKC3P8tqsKc98xmWNzrzDtRLMiMPL8wBuTGsMnR',
      color: 'Blue',
    },
    tokenHash,
  },
  waitForTransactionProcessed: true,
});
```

After execution, a new NFT is minted for **owner**, and its metadata is stored on-chain. The NFT can later be queried using `my_custom_hash`.

---

## **Minting Using a Session Contract**

Alternatively, you can mint an NFT using a session contract, which provides an alternative approach by first registering the token owner's key with the contract (see [Register NFT Owner](#register-nft-owner)). The session contract then proceeds to execute the minting operation, storing the owner's details and token metadata on-chain. By using this method, you can offload more complex logic and workflows to the session contract, as well as enabling the dynamic registration of ownership and other custom processes.

```ts
const tokenHash = 'my_custom_hash';

await client.mint(
  {
    params: {
      sender: sender.publicKey,
      paymentAmount: String(5_000_000_000),
      signingKeys: [sender],
    },
    args: {
      tokenOwner: owner.publicKey,
      tokenMetaData: {
        ucid: tokenHash,
        ipfs_cid: 'QmbWqxBEKC3P8tqsKc98xmWNzrzDtRLMiMPL8wBuTGsMnR',
        color: 'Blue',
      },
      tokenHash,
    },
    waitForTransactionProcessed: true,
  },
  true // Passing `true` to call session Wasm
);
```

### **Key Differences:**

| **Method**                   | **Description**                                                                    |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| **Direct Minting**           | Calls the contract’s `mint` entry point directly.                                  |
| **Session Contract Minting** | Uses a Wasm "client" contract call for execution, allowing more complex workflows. |

---

## **Balance of Token Owner**

The `balanceOf` method retrieves the balance of a specific token owner. It can operate in two modes:

1. **Direct Query Mode**: When provided with a direct token owner, it queries the blockchain state to find the balance from the `balances` dictionary.
2. **Session Mode**: When provided with a `wasm` and `keyName`, it executes a session transaction to query the token balance and store it.

### **Direct Query Mode Example**

This example directly queries the balance of a token owner by passing the owner's public key:

```ts
const tokenOwnerBalance = await cep78.balanceOf(ali.publicKey);
console.info(tokenOwnerBalance); // Should return a string representing the balance (e.g., '1')
```

### **Session Mode Example**

This example uses session mode to query the balance and store it under a specified key:

```ts
const keyName = 'stored_balance_of_token';
const balanceOfArgs = {
  keyName,
  tokenOwner: bob.publicKey,
};

const balanceResult = await cep78.balanceOf({
  params: {
    sender: ali.publicKey,
    paymentAmount: String(2_500_000_000), // 2.5 CSPR
    signingKeys: [ali],
  },
  args: balanceOfArgs,
  waitForTransactionProcessed: true,
});
```

# **Transfers**

## **Basic Transfer**

The following example demonstrates how to transfer a token from the **owner** to a **recipient**:

```ts
const params: TransactionParams = {
  sender: owner.publicKey,
  paymentAmount: String(5_000_000_000), // 5 CSPR
  signingKeys: [owner],
};

const transferArgs: TransferArgs = {
  source: owner.publicKey,
  target: ali.publicKey,
  ...(identifierMode === IDENTIFIER_MODE[IDENTIFIER_MODE.Hash]
    ? { tokenHash: tokenIdentifier }
    : { tokenId: tokenIdentifier }),
};

const transferResult = await cep78.transfer({
  params,
  args: transferArgs,
  waitForTransactionProcessed: true,
});
```

After execution, the token is successfully transferred from **owner** to **ali**.

---

## **Transfer on Behalf of an Owner**

This example transfers a token from an **account owner** to a **recipient** (**bob**) when the **direct caller** (**ali**) has been pre-approved to manage the owner’s tokens (see [Approve NFT Operator](#approve-nft-operator)).

```ts
const params: TransactionParams = {
  sender: ali.publicKey,
  paymentAmount: String(5_000_000_000), // 5 CSPR
  signingKeys: [ali],
};

const transferFromArgs: TransferFromArgs = {
  source: owner.publicKey,
  target: bob.publicKey,
  ...(identifierMode === IDENTIFIER_MODE[IDENTIFIER_MODE.Hash]
    ? { tokenHash: tokenIdentifier }
    : { tokenId: tokenIdentifier }),
};

const transferFromResult = await cep78.transferFrom({
  params,
  args: transferFromArgs,
  waitForTransactionProcessed: true,
});
```

In this case, **ali** acts as an intermediary, transferring the token from **owner** to **bob** after obtaining prior approval.

---

## **Transfer Using Session Contract**

Alternatively, you can perform the token transfer using a **session contract**, which offloads the execution logic for the transfer. The session contract handles the token transfer between the source and target, ensuring that the operation is executed securely on-chain, and stores the result (such as the receipt name and owned tokens dictionary key) in the acount context.

```ts
const params: TransactionParams = {
  sender: owner.publicKey,
  paymentAmount: String(5_000_000_000), // 5 CSPR
  signingKeys: [owner],
};

const transferArgs: TransferArgs = {
  source: owner.publicKey,
  target: ali.publicKey,
  ...(identifierMode === IDENTIFIER_MODE[IDENTIFIER_MODE.Hash]
    ? { tokenHash: tokenIdentifier }
    : { tokenId: tokenIdentifier }),
};

const transferResult = await cep78.transfer(
  {
    params,
    args: transferArgs,
    waitForTransactionProcessed: true,
  },
  true // Passing `true` to call session Wasm
);
```

In this example, the callSessionWasm flag is set to true, triggering the transfer to be processed via the session contract.

## **Retrieve Token Owner**

The `ownerOf` method retrieves the owner of a specific token by its identifier (either token ID or hash). It can operate in two modes:

1. **Query Mode**: Directly queries the blockchain state to find the token's owner.
2. **Session Mode**: Uses a smart contract session to query and store the owner’s address.

### **Query Mode Example**

This example directly queries the owner of a token using its identifier (token ID or token hash):

```ts
const tokenHash = 'my_custom_hash';
// Directly query the owner of the token using its hash
const tokenOwner = await client.ownerOf(tokenHash);
```

In this mode, the owner of the token is queried from the blockchain state directly, without needing to use a session. If no owner is found, it will return undefined.

### **Session Mode Example**

This example uses session mode to query the owner of a token and store the result under a specified key:

```ts
const tokenHash = 'my_custom_hash';
const keyName = 'stored_owner_of_token';
const ownerOfArgs = {
  keyName,
  tokenHash, // Use the tokenHash as the identifier
};

const ownerResult = await cep78.ownerOf({
  params: {
    sender: ali.publicKey,
    paymentAmount: String(2_500_000_000), // 2.5 CSPR
    signingKeys: [ali],
  },
  args: ownerOfArgs,
  waitForTransactionProcessed: true,
});
```

## **Register NFT Owner**

The `register` method registers a new token owner in the NFT contract. This is required when the contract’s **OwnerReverseLookupMode** is set to **Complete** or **TransfersOnly**. Registering an owner allows them to mint or receive NFTs.

### **Usage Example**

```ts
const registerResult = await cep78.register({
  params: {
    sender: bob.publicKey,
    paymentAmount: String(5_000_000_000), // 5 CSPR
    signingKeys: [bob],
  },
  args: {
    tokenOwner: bob.publicKey,
  },
  waitForTransactionProcessed: true,
});
```

## **Approve NFT Operator**

The `approve` method grants approval to an operator to manage a specific NFT on behalf of the owner. This is used to allow another account (operator) to transfer or manage the specified NFT.

### **Usage Example**

```ts
const tokenHash = 'my_custom_hash';
const approveResult = await cep78.approve({
  params: {
    sender: ali.publicKey,
    paymentAmount: String(5_000_000_000), // 5 CSPR
    signingKeys: [ali],
  },
  args: {
    operator: bob.publicKey,
    tokenHash, // Token hash to approve
  },
  waitForTransactionProcessed: true,
});
```

## **Set Approval for All NFTs**

The `setApprovalForAll` method allows an NFT owner to grant or revoke approval for an operator to manage all NFTs owned by the sender. This is used to control whether an operator can manage every NFT owned by the sender.

### **Usage Example**

```ts
const setApprovalResult = await cep78.setApprovalForAll({
  params: {
    sender: ali.publicKey,
    paymentAmount: String(5_000_000_000), // 5 CSPR
    signingKeys: [ali],
  },
  args: {
    operator: bob.publicKey,
    approveAll: true, // true to grant approval, false to revoke
  },
  waitForTransactionProcessed: true,
});
```

The `upgrade` method allows upgrading an existing NFT contract on the Casper network by deploying a new version while retaining the existing data.

### **Usage Example**

```ts
const collectionName = 'TEST_CEP78',
  eventsMode = EVENTS_MODE.NoEvents,
  paymentAmount = String(600_000_000_000);

const params: TransactionParams = {
    wasm, // optional, takes default Wasm in wasm folder if not set
    sender: sender.publicKey,
    paymentAmount,
    signingKeys: [sender],
  },
  args: UpgradeArgs = {
    collectionName,
    eventsMode,
  },
  transactionResult: TransactionResult = await cep78.upgrade({
    params,
    args,
    waitForTransactionProcessed: true,
  });
```

The upgrade method deploys the Wasm file to upgrade an NFT contract. It retains existing data and updates the contract's behavior based on the provided arguments (e.g., eventsMode, aclPackageMode). If waitForTransactionProcessed is true, it waits for the transaction to complete and returns the result.

# Environment Variables for Casper CEP-78 Integration

This `.env` file contains essential environment variables for configuring the examples and e2e tests, including RPC and SSE endpoints, private key handling, and cryptographic settings.

## Configuration Variables

| Variable Name        | Description                                                                                                                         |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `RPC_URL`            | The URL of the Casper JSON-RPC server used for interacting with the blockchain. Defaults to `http://localhost:11101/rpc`.           |
| `SSE_URL`            | The URL of the Casper SSE (Server-Sent Events) endpoint for real-time event streaming. Defaults to `http://localhost:18101/events`. |
| `CHAIN_NAME`         | The name of the Casper blockchain network. Defaults to `casper-net-1`.                                                              |
| `PRIVATE_KEY_FAUCET` | The private key of the faucet account. Can be a **file path**, a **PEM-encoded base64 string**, or a **raw base64 key**.            |
| `PRIVATE_KEY_USER_1` | The private key of the first user. Can be a **file path**, a **PEM-encoded base64 string**, or a **raw base64 key**.                |
| `PRIVATE_KEY_USER_2` | The private key of the second user. Can be a **file path**, a **PEM-encoded base64 string**, or a **raw base64 key**.               |
| `SECRET_KEY_NAME`    | The default filename for private keys when using directory-based paths. Defaults to `secret_key.pem`.                               |
| `SECRET_KEY_ALGO`    | The cryptographic algorithm used for private keys. Defaults to `ED25519`, unless `SECRET_KEY_ALGO` is set to `SECP256K1`.           |

Automatically detects whether a provided private key is a **file path**, a **PEM-encoded base64 string**, or a **raw base64 key**.

### 1. Using a File Path

If `PRIVATE_KEY_FAUCET`, `PRIVATE_KEY_USER_1`, or `PRIVATE_KEY_USER_2` is set to a valid **file path**, the system will read the file and extract the key.

Example:

```env
PRIVATE_KEY_FAUCET=/casper/casper-nctl/assets/faucet/secret_key.pem
```

or, if the filename is omitted, it defaults to `SECRET_KEY_NAME`:

```env
PRIVATE_KEY_FAUCET=/casper/casper-nctl/assets/faucet/
```

### 2. Using a PEM-Encoded Base64 Key

You can also provide a full **PEM-formatted** private key directly in the `.env` file:

```env
PRIVATE_KEY_FAUCET=-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBg...\n-----END PRIVATE KEY-----
```

Will detect this format and use it as-is.

### 3. Using a Raw Base64 Key

Alternatively, you can provide a **raw base64-encoded key** without PEM formatting:

```env
PRIVATE_KEY_FAUCET=nMIIEvQIBADANBg...
```

If the system detects a raw base64 key, it will automatically format it into the correct PEM structure before use.

## Event Handling

# CEP-78 Event Handling

As CEP-78 above 1.2 supports two events modes - `CEP47` and `CES` we have two parsers as a part of this SDK.

CEP-78 tokens support the [Casper Event Standard (CES)](https://github.com/make-software/casper-event-standard), allowing event-based interactions. Tokens can be installed with or without event logging, as described [here](../cep-78-enhanced-nft/README.md#eventsmode).

If a token is installed with `EventsMode` set to CES, you can listen for token events using the `EventStream` from the `casper-js-sdk`.

## Setting Up Event Streaming

To start listening for CEP-78 events, set up the `EventStream` as follows:

```ts
import { CEP78Client } from 'casper-cep78-js-client';

const cep78 = new CEP78Client(
  'http://localhost:11101/rpc', // RPC URL
  'http://localhost:18101/events', // SSE URL
  'casper-net-1' // Chain name
);

// Set the contract hash and start listening for events
cep78
  .setContractHash(
    'hash-0885c63f5f25ec5b6f3b57338fae5849aea5f1a2c96fc61411f2bfc5e432de5a'
  )
  .startEventStream();
```

## Listening for Events

You can subscribe to token events by attaching event listeners:

```ts
const listener = (event) => {
  console.info(event.name); // Example: 'Burn'
  console.info(event.data); // Event-specific data
};

cep78.on('Burn', listener);
```

## Removing Event Listeners

### Remove a Specific Listener

To remove a specific event listener, use `off()`:

```ts
cep78.off('Burn', listener);
```

### Remove All Listeners for an Event

To remove all listeners attached to a specific event:

```ts
cep78.removeListenersForEvent('Burn');
```

### Remove All Listeners

To remove all event listeners across all events:

```ts
cep78.removeAllListeners();
```

## Event Stream Lifecycle

### Starting the Event Stream

Call `startEventStream()` to begin listening for events:

```ts
cep78.startEventStream();
```

### Stopping the Event Stream

To stop listening for events, use:

```ts
cep78.stopEventStream();
```

Stopping the event stream will also prevent any new events from triggering listeners.

## Best Practices for Event Handling

- Ensure you stop the event stream when it is no longer needed to avoid unnecessary resource usage.
- Always remove event listeners that are no longer required using `off()`, `removeListenersForEvent()`, or `removeAllListeners()`.
- If you need to temporarily disable event handling, consider stopping the event stream instead of removing all listeners.
- Use the `ces-js-parser`'s event parser to efficiently decode event payloads.

## `waitForTransactionProcessed`

The `waitForTransactionProcessed` method waits for a transaction to be processed and resolves once the transaction is found. It also handles a timeout to prevent the operation from running indefinitely. Additionally, an optional SSE URL can be provided.

### Parameters:

- `transactionHash` (string): The hash of the transaction you want to wait for.
- `timeout` (number, optional): Timeout in milliseconds. Defaults to `defaulTransactionTimeout` if not provided.
- `sseUrl` (string, optional): Optional SSE URL. If provided, updates the client's SSE URL.

### Returns:

- A `Promise` that resolves to the `TransactionProcessedEvent` when the transaction is found.

### Throws:

- An `Error` if the transaction processing times out or if an error occurs during subscription.

---

## `getTransactionResult`

The `getTransactionResult` method retrieves and parses the transaction result for a given transaction hash.

If the transaction was not successful, this method throws:

- `ContractError` if the failure is due to an operational error.
- A generic `Error` containing the original error message for other failures.

### Parameters:

- `transactionHash` (string): The hash of the transaction to retrieve.

### Returns:

- A `Promise` resolving to the `InfoGetTransactionResult` containing transaction details.

### Throws:

- `ContractError` if the transaction failed due to an operational error.
- `Error` with the original error message if another failure occurs.

## Example Usage

```ts
// Example of using getTransactionResult:
try {
  const result = await client.getTransactionResult(transactionHash);
  console.info('Transaction result:', result);
} catch (error) {
  console.error('Error fetching transaction result:', error);
}

// Example of using waitForTransactionProcessed:
client
  .waitForTransactionProcessed(transactionHash, 5000)
  .then((event) => {
    console.info('Transaction processed:', event);
    // Optionally fetch the transaction result after processing the event
    return client.getTransactionResult(transactionHash);
  })
  .then((result) => {
    console.info('Transaction result after event:', result);
  })
  .catch((error) => {
    console.error('Error processing transaction:', error);
  });
```

## Best Practices

- When using \`waitForTransactionProcessed\`, ensure that the timeout is set appropriately to avoid unnecessary waiting.
- Use \`getTransactionResult\` after the transaction has been processed if you need to fetch the result after the event is triggered.
